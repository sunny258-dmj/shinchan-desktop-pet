# 桌宠检查与修复报告

完成日期：2026-09-09。检查范围为本项目的原图、Qt 宿主、状态读取、控制命令及启动入口。原脚本备份见 `original-scripts.zip`。

## 最重要的发现

原图虽为 3072×4576，但 11 行人物实际高度和间距不同。直接按 384×416 等分裁剪会切到头顶，并混入下一行动作。已识别 88 个主要人物区域，用 `spritesheet-layout.json` 校正运行时取帧；统一缩放和落脚基线，跳跃行保留离地变化。原图哈希与布局文件绑定，替换素材时会要求重新校验取帧信息。

原来的左右凝视映射相反，向下会显示背影；现在左右与屏幕方向一致，垂直方向回到正面。素材本身缺少可靠的正上/正下姿势，未伪造完整八方向效果。

工作行最后一帧突然从电脑后站起，等待行混有躺倒动作；若干源帧的星星、烟雾跨出人物所在区域。本次选择适合状态、主体完整且装饰没有截断的帧播放，保留所有原始图像。待机节奏放缓，工作、等待、检查与失败动作保持各自语义。

## 程序修复

| 问题 | 修复方式 |
|---|---|
| 相同 time_created / 分页边界漏读 | 新增记录使用 rowid 游标 |
| 已有工具行更新为失败时漏报 | 跟踪 pending/running 行的 status 更新 |
| 助手文本被猜成用户消息 | 联接 message 表读取 role |
| 完成后仍显示读取文件、旧文件名 | 非工具事件清空旧标签与摘要 |
| 不同会话共享保活导致残留气泡 | 活跃会话分别保活 |
| 相同状态不更新新消息 | 消息内容独立于动画变化更新 |
| 只改变步数时不刷新 | 渲染签名包含状态、步数和完整摘要 |
| 隐藏桌宠但气泡还在 | 主窗口与所有气泡统一可见性 |
| 多任务命令写了 tasks 却不显示 | 接入 state.json.tasks 并规范数值 |
| 无 state.json 时进度文件不工作 | 进度轮询独立运行，删除时清理卡片 |
| 上边缘多气泡互相覆盖 | 按总高度布局，限制到当前屏幕 |
| 逐字输出测量当前短文本，后续被截断 | 始终按完整文本计算高度 |
| 任务卡过于透明、样式影响内部标签 | 白色不透明底与独立卡片选择器 |
| 控制器用 PowerShell 执行 .py | 统一调用 start-pet.ps1 → pet-start.py |
| PID 残留/并发启动风险 | 操作系统文件锁与退出清理 |
| 启动器残留进程占用工作目录 | 控制器等启动入口返回再报告结果 |
| 文档中的位置保存和召回未实现 | 补上位置文件、重置位置和全局快捷键 |

事件 SQL 仅投影状态、工具描述、文件名和关键词，不把思考、消息、命令或工具输出正文交给气泡。诊断日志也改为同样的结构化事件视图。

## 已知范围与限制

- 原图正上/正下凝视缺失，本次使用正面回退；少量源帧在比例、装饰和姿态上仍有美术差异，未重新生成图像。
- 屏幕容量不足时隐藏放不下的任务卡片，未实现滚动卡片容器。多显示器逻辑按当前屏幕布局，未在不同 DPI 的多显示器实机上逐一验证。
- Ctrl+Alt+P 已实现；其他软件占用时保留命令召回入口，未强占快捷键。
- 自动化浏览器的本地 URL 策略拒绝打开动画对比 HTML，未绕过该限制。Qt 渲染已独立验证；HTML 可由用户在本地浏览器打开。
- TeleAgent 实测通过的是当时的 14 项测试；最终 20 项结果是本地独立运行，二者没有混为一次测试。
- 自动安全审查拒绝了旧失败测试的临时目录删除操作（返回 blocked by policy）。系统临时目录中的 `shinchan launch rbf7x2ij` 与 `shinchan launch bvfkm85o` 保留，未绕过该限制；最终启动测试已正常结束并自行清理。
